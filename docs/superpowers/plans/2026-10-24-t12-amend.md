# T12 Amend 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 实现 v6 §7.4.2--§7.4.3、§20、§54 不变量 31--33 与 §65 规定的 `Amend`：目标总量语义、常规订单与 Stop 订单的优先级规则、预留调整令牌，以及失败原子性。

**架构：** 先以不可变快照建立 `AmendPlan`，完成订单候选、价格/数量/TIF/保护条件、到期索引、预留令牌与可执行性预检；仅在所有校验成功后按计划提交。Reference 与 Production 各自实现计划与提交路径，差分测试逐命令比较原序事件、深度、订单、到期和优先级，不让 Reference 调用生产实现。

**技术栈：** Rust 2024、现有 `matching-domain`、`matching-orderbook`、`matching-risk`、`BTreeMap`/`HashMap`、现有 `proptest`。除非完成依赖审查，不新增第三方依赖。

**规格：** `assignment/rust_cex_matching_engine_development_spec_v6.md` §7.4.2--§7.4.3、§20、§54（31--33）、§58、§65、§77；`assignment/tasks/T12_P4_amend.md`。

## 全局约束

- 本计划不授权实现、提交或推送 T12；实施前须取得用户明确授权。
- 不伪造预留、签名、风险或资金闭环。当前仓库不存在 `ReservationState`、`AssetReserve`、`RiskKeySet` 或 `ReservationAdjustmentToken` 的实现，必须先补齐可本地验证的真实契约。
- 所有预检不得修改订单簿、StopBook、到期索引、预留版本或 priority；任一失败保留字节等价的业务状态。
- 不在撮合、Amend 或 Stop 热路径访问网络、数据库、时钟或远程 RPC；所有数值计算使用 checked math。
- 不把 T13 CancelReplace、资金结算、HA、gateway 或非本任务协议顺手实现。
