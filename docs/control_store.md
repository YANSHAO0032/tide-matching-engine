# 外围控制存储与游标

`matching-control` 是同步外围适配器，不在撮合线程内发起网络请求。etcd 客户端使用线性一致读取和服务端事务；每次操作为端点探测和请求分配共享期限，写入响应丢失时结果未知，调用方不得把该情况当成未提交并盲目重试。底层 DNS 解析及部分系统连接调用可能超过配置期限，不能将该期限作为硬实时保障。端点限定为 HTTPS，或显式允许的 IPv4 回环测试地址；当前接口尚未提供认证凭据、定制信任根或客户端证书配置，不能据此声称具备完整生产部署能力。端点配置和 TLS 身份须由部署方保护。

路由快照绑定集群身份并使用 CRC32C 校验。`EtcdRouteAuthority` 的写入需要独占租约，并在同一事务中核验租约身份与快照版本。`RouteCoordinator::start_monitor` 启动前续约并核验权威，随后在外围周期执行同样的检查；失败时关闭入口。etcd 适配器拒绝不小于申请租约时长的监视间隔，调用方还须考虑网络延迟。监视存在间隔和网络延迟，不能保证失权后已入队命令立即停止。尚不能作为完整高可用路由控制面使用。

监视发现权威失效或监视循环发生异常时还会标记队列，工作线程和批处理在开始处理每条变更前检查该标记；正常停止仍保留排空行为。检查后已开始处理或已追加 WAL 的命令可能继续，远端失权到监视发现之间也存在窗口，因此该标记不构成完整的持久提交 fencing。

协调器构造失败或退出时，本进程保留权威对象及集群登记，直至分片到达排空屏障；无法建立排空线程或无法确认排空时保留权威。远端租约可能在排空期间到期，本地对象仍存活不代表远端所有权仍有效。

协调器构造期间先在各分片队列顺序点暂停变更，再读取并核验权威，在恢复前续约并重新读取核对路由。路由权威默认要求监视线程接管；在监视启动前分片保持暂停，也不允许直接更新路由。单机文件权威不依赖续约，可在校验后直接恢复。监视线程启动确认失败时关闭入口；默认控制等待为 5 秒，也可显式指定。此过程不覆盖调用构造器之前已经接受或执行的命令，也不能使多个分片的恢复操作原子发生，续约成功也不能保证恢复后租约持续有效。

正式命令分片可通过 `PlaceSupportConfig::require_route_authority` 从工作线程创建时即暂停变更；使用此配置启动和恢复后，须由协调器确认权威才能处理变更。低层分片可通过 `ShardConfig::require_route_authority` 启用相同的启动暂停。需要监视的权威只接受从暂停状态启动的分片，检查失败会关闭入口；这不能撤销此前已执行的命令。正式命令选项是部署时的可信配置，不写入业务快照，恢复时必须再次启用。本选项不解决远端失权与持久提交之间的原子性。

路由键须以斜杠开头，仅包含 ASCII 字母、数字、斜杠、下划线和连字符，不能以 `/owner` 结尾或包含连续斜杠；键长度至多 1018 字节，为租约键后缀预留空间。部署时还须通过存储访问策略隔离其他用途的键，避免非路由客户端写入租约命名空间。

监视期间可通过有界控制入口提交路由版本更新；直接更新和监视更新均在安装后、恢复分片前续约并重新核验，监视更新结束后再次续约核验。控制消息超过截止时间后不再主动入队；已经入队的消息及已发出的持久写入仍可能完成。等待超时表示更新结果未知，应重新查询权威状态，不能直接假定未提交。控制入口繁忙时请求尚未入队。恢复前检查仍不能保证之后租约不会失效。

游标路径按集群、分片及 sink 隔离。发布者先通过带租约的事务认领分片并递增持久纪元；每次推进 checkpoint 时，存储端在同一事务比较当前租约身份、发布者纪元和游标记录版本。位置不得倒退，版本和纪元使用 checked 加法；记录格式包含 CRC32C，损坏时返回错误。管理员维护的必需 sink 集合也使用持久版本比较和 CRC32C；授权由控制存储访问策略和调用方负责。

调用方须按时刷新租约，刷新失败立即停止发布。撤销、续约失败或核验失败会使本进程中的令牌副本失效；本地未失效不证明远端租约有效。`verify` 只证明检查时刻的状态，不能消除检查与外部发送之间的竞态；接收端需要参与 fencing，完整发布链、晋升恢复和基于持久游标的日志回收尚未接入。不得将当前游标事务测试当成这些链路的验收证据。

`FencedLog` 为复制分片提供外围连续日志。它按集群和分片独占写者租约，在持久纪元下将完整 WAL 记录拆成最多 192 KiB 的分块，并通过比较写权的事务登记不可变复制意图；意图本身不推进提交水位。收到备节点持久确认后，写者再次比较租约、纪元、旧水位和意图，以事务登记记录并推进连续水位；每次只能提交下一序号。读取意图及已确认记录时验证分块长度、元数据及 WAL 校验和与身份。取得后继写权时检查整个已确认前缀及纪元顺序，并在检查结束后再次核对租约与水位。存储故障或提交结果未知会使当前写者失效，调用方须通过权威前缀恢复，不得假设未提交。

此协议保留未提交分块，不提供日志或孤儿分块回收；控制存储容量不足时写入失败。它不代替本地 WAL、备节点确认、状态重放、digest 核验或外部发布者 fencing，也不降低现有 WAL 单条载荷上限。受信访问策略必须防止其他客户端篡改日志命名空间；完整 HA 提交链和故障恢复通过前不能开放生产流量。

外围复制帧可通过调用方提供的已认证双向流传输 WAL 批次；调用方负责认证、连接并发上限、读写期限和出错后关闭连接。帧以 `RPL1`、大端长度、记录数、逐条长度与 WAL 记录以及 CRC32C 组成；确认以 `RPA1`、集群与分片身份、纪元、起止序号和 CRC32C 组成。接收端先验证完整帧与每条记录，再核对活动 owner、纪元和精确复制意图；备节点按身份、纪元和连续序号预检，实际同步后才发送确认。发送端校验确认的身份、纪元和范围。帧大小有上限且至少容纳一条最大 WAL 记录，超出帧上限的批次须在记录边界拆分。网络中断、部分帧和结果未知均不是成功确认。

`ReplicatedAppender` 先同步本地 WAL，再通过容量为一的外围线程登记复制意图并发送备节点；确认后逐条执行调用方提供的写权事务，全部确认后才交出复制 ACK。网络读写和权威提交共享批次截止时间；控制存储单次调用使用其配置超时与批次剩余时间中的较小值。超期后不再主动发起新操作，已发出的请求仍可能提交，结果必须按权威状态恢复。底层系统连接和 DNS 调用仍可能超过配置期限。线程或续租失败时本地复制健康状态变为不可用，批处理器在发现该状态后不再接受新的 WAL 追加。

`FencedStandbyReplica` 将复制批次与持久纪元栅栏置于同一独占访问顺序。`activate_replica_writer` 以控制存储事务核验集群、分片、租约和纪元，在接任顺序点安装持久栅栏并返回实际 WAL 水位。安装后仍拒绝复制，须先核对权威前缀并通过 `confirm_reconciled` 重新验证写权，才可接收批次。重启时校验栅栏及恢复水位，并重新执行上述步骤；失败暂停接收，已安装的纪元不会回退。租约编号本身不是认证凭据；连接身份认证、权威前缀核对和逐条复制意图校验仍由调用方负责，目前尚无完整的生产接任链路。

`reconcile_local_standby` 适用于同进程持有真实备节点和写者的协调：安装栅栏后从备节点独占清单与 WAL 读取持久记录，逐条核对权威提交记录及旧纪元复制意图，全部核对后按顺序事务采纳已同步尾部，重新核验写权后开放复制。中途失败或事务结果未知时写者失效，重新取得写权后可从已推进的连续水位再次协调。调用方仍须验证快照内容、独占 WAL 目录并完成业务重放；该接口不提供跨主机传输、连接认证或正式分片接入。

栅栏请求帧 `RFE1` 和确认帧 `RFA1` 绑定集群、分片、写者纪元、租约及 CRC32C；确认另携带备节点持久水位。接收方先比较调用方提供的已认证连接身份，再核验控制存储写权并同步栅栏。栅栏请求成功只返回水位，备节点仍保持暂停，不能替代跨主机前缀协调。调用方负责认证连接、持有备节点单写者并在出错时关闭连接；每次底层读写使用剩余总期限，底层系统调用仍可能超过配置期限。

前缀传输使用逐条 `RFR1` WAL 记录帧和 `RFT1` 结束标识。接收端按栅栏确认的边界校验分片、连续序号、历史纪元、记录长度及校验值；单条记录长度有界。逐条回调仅供暂存或校验，完整前缀和权威复制意图核对完成前不能提交。连接认证、栅栏持有、权威事务及接任会话的编排仍由调用方负责，单独使用传输帧不能证明前缀已协调。

`serve_fenced_prefix` 在同一次备节点独占访问内安装栅栏、读取真实 WAL 并发送前缀，发送前再次核验写权；完成发送后备节点仍暂停。该接口不执行权威尾部采纳，也不提供连接认证或主节点状态恢复。

`reconcile_remote_prefix` 从调用方认证的连接接收完整前缀，在全部核对权威提交记录及复制意图后事务采纳已同步尾部；读取或事务失败使写者失效。当前实现暂存整个前缀，分配失败即停止；它不完成备节点重新开放的确认，也不完成主节点 WAL 恢复及业务重放。

`reconcile_authenticated_remote_prefix` 在该流程前检查本写者的证书租约绑定，并要求固定对端证书的 TLS 流。调用方仍须选择安全 TLS 配置、验证快照并完成主节点恢复；低层接口仍可独立调用。

外围可使用 `replica_client_config`、`replica_server_config` 和 `TlsReplicaStream` 建立相互认证的 TLS 流；双方配置显式信任根并固定预期对端证书。信任根、证书、私钥、节点身份映射及轮换由部署方管理。现有低层复制接口仍接受普通流，正式调用链必须明确要求认证，不能仅凭类型或测试断言所有连接已经认证。

`FencedLog::acquire_bound` 可在分配写者纪元的同一事务中，将证书与写者租约绑定；绑定键随租约失效，绑定写者推进日志时的事务也比较该证书。`verify_bound_replica_writer` 同时比较租约、纪元和证书。认证复制和接任入口使用此绑定；旧的未绑定低层接口仍然存在。

`serve_authenticated_fenced_prefix` 使用已完成 TLS 握手的实际对端证书核验写者租约绑定，再提供栅栏前缀。该入口依赖安全的双向 TLS 配置；其他低层入口仍允许未绑定连接。

`receive_authenticated_replica_resume` 同样在处理恢复确认前核验实际 TLS 对端证书与租约绑定。调用方仍须先完成主节点恢复，并在正式服务中限制使用其他低层入口。

`receive_authenticated_replication_batch` 在读取批次前及逐条意图核验时比较实际 TLS 对端证书、租约和纪元，并核对完整复制意图；备节点同步完成后才确认。该入口不替代接任栅栏，正式服务仍须保证单写者并使用认证连接。

`confirm_authoritative_replica` 供备节点核对自身 WAL 与权威已提交记录：水位和每条记录一致并重新核验写权后才开放复制。认证恢复入口在主节点重放校验后请求备节点执行此确认。

远端恢复请求 `RRC1` 与确认 `RRA1` 绑定写者身份、持久水位及 CRC32C。备节点核对认证身份和自身水位后执行权威前缀确认，再返回确认帧。确认帧发送或刷新报错时备节点重新暂停；发送成功但响应丢失时备节点可能已经开放，调用方须按结果未知处理。调用方须在发送请求前完成主节点恢复。

同一写者重试恢复确认时，备节点先核验当前写权并暂停复制，再重新核对自身水位和权威前缀；水位已变化时拒绝旧请求并保持暂停。

认证复制与接任已连接分片工作线程。真实 etcd 和双向 TLS 测试覆盖同机跨进程终止与接任，包含恢复旧主挂单并在接任后成交；该测试中备节点与旧主同时终止并由接任进程重开。生产监听服务、跨主机网络分区及断电故障验证仍需完成，不能把局部测试视为完整 HA。

`AuthenticatedRecovery` 使用证书绑定的写者和双向 TLS，先协调备节点连续前缀，再将本地 WAL 与权威记录逐条核对；业务重放的状态和事件摘要与可信摘要一致后，才请求备节点恢复复制。摘要可以由调用方提供，也可以从当前权威水位的持久检查点读取。当前恢复要求完整创世 WAL；TLS 信任配置及路由权威由调用方提供，不包含选主；本地持久前缀超前时，在重放摘要核验后依据权威前缀协调尾部。

即使清单已登记快照，认证恢复仍从未回收的创世 WAL 核对并重放，不把快照自身校验和作为权威证明。若创世前缀已经回收，当前恢复入口会拒绝启动，需依靠后续经过权威认证的快照恢复机制。

权威摘要检查点按分片序号保存状态摘要和从创世起的有序事件摘要。登记事务同时比较证书绑定写权、当前提交水位和检查点版本；检查点纪元须与该水位的最后一条 WAL 记录一致，同一序号的内容不可覆盖。重复相同内容可重试；失权、冲突、期限或事务结果未知时写者停止。接任者读取摘要时须检查当前水位、最后记录纪元及有效写权；没有可信检查点时，只有满足下述创世协议条件才能恢复。摘要必须由分片实际顺序点产生，该持久原语本身不证明调用方提供的数据正确，也不负责回复前登记。

复制写入器通过容量为一的外围队列在持有写权的同一线程登记摘要；批处理器只接受当前完整备节点持久提交水位。分片在安装候选状态并回复前计算和登记摘要；登记失败、超时或回复结果未知时停止后续写入。权威 WAL 已提交而摘要尚未登记时，可从较早检查点核验并重放后缀；真实 etcd 与双侧 WAL 的组合测试覆盖登记前受控故障，该测试不等同于断电。

摘要检查点与最新摘要序号在同一权威事务中登记。接任者可在有效写权下读取不超过当前 WAL 水位的最新检查点，并核对记录纪元；若当前水位尚无摘要，旧检查点仅是重放核验边界，不能直接证明后缀状态。认证恢复按序重放并在该检查点核对状态和事件摘要，再继续执行权威后缀。

认证复制写入器在空权威日志中持久登记创世协议标记，标记只能在没有已提交记录时以写权事务建立。没有任何摘要检查点时，认证恢复要求该标记和完整创世 WAL：此前未成功登记摘要的批次不能按此协议回复，恢复可从可信初始配置重放这些权威记录。已有记录但缺少标记的旧日志不允许事后补建标记；此路径依赖受信访问策略和所有写者遵守回复前摘要协议，已通过同进程受控首批故障组合测试；该故障窗口的真实进程终止仍需验证。

本地 WAL 落后时，认证恢复先完成备节点与权威前缀协调，逐条核验本地前缀与权威后缀，再逐条同步本地 WAL 并登记清单；补齐后才能重放并校验状态。发生错误或写权失效时停止启动并重新协调。真实 etcd 和本地文件测试覆盖部分记录完成登记后失权，以及新纪元核验前缀后继续写入；这不等同于系统调用内部断电测试。当前路径要求保留完整创世 WAL。
