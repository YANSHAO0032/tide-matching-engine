# 命令与事件身份

当前正式命令入口使用 `CommandEnvelope` 携带命令身份、会话、客户端序号、可选市场／用户、路由版本及审计时间。审计时间仅保存为输入信息，不参与撮合或逻辑时间。`EventEnvelope` 按原序携带集群、分片、根命令序号、从零开始的事件索引、命令身份、逻辑时间、事件所属市场及业务载荷。已提供版本化正式命令二进制编码，开发环境空状态入口使用该编码写入 WAL；正式入口提供有限的分片内去重，持久入口可从可信快照及已提交 WAL 恢复去重窗口。

## 正式入口支持范围

| 命令或范围 | 当前支持 |
|---|---|
| 市场范围 `MassCancelShard` | 在持有真实 `ReservationRegistry` 的分片中执行；`market_id`、scope 市场和路由版本须一致，当前仅支持无 envelope 用户身份的市场范围。 |
| 其他 MassCancel 范围 | 未通过正式入口开放；跨市场和用户控制须等待相应路由及控制契约。 |
| 普通限价 GTC / PostOnly | 使用可信市场资金策略、签名密钥和容量配置；不支持正式市价、IOC/FOK、冰山或 Stop 下单。市场存在未触发 Stop 时拒绝此下单。 |
| 用户控制 FenceOnly | 校验期望主节点 epoch，更新本分片用户下限；FenceAndCancelAll 当前拒绝。 |
| 市场管理 | 持久入口支持创建、更新、开始和结束时段、开市、暂停、恢复及关市；使用 `require_managed_markets` 时，未创建市场的正式业务请求被拒绝。配置更新和 PreOpen 重校验的当前边界见 [市场生命周期](market_lifecycle.md)。 |
| Cancel、Amend、CancelReplace、Stop 下单 | 尚未通过正式入口开放。旧 runtime 低层入口只在无登记表模式使用，不代表完整正式生命周期。 |

正式模式启动须提供显式绑定市场的订单簿、完整登记表及初始逻辑时间；启用正式下单时初始活动订单必须为空，以免缺失客户端订单身份索引。启动核验所有活动订单与预留归属，并拒绝初始时间已到期的普通及 Stop GTD 订单。受管理市场保存生命周期和时段；对于未受管理的既有入口，调用方仍须保证初始订单状态与逻辑时间来自同一可信执行点，且 DAY 订单所属交易时段有效。调用方须保证输入来自可信执行上下文，当前不提供管理权限认证。正式模式拒绝旧低层 Mutation，避免绕过预留归属。查询和屏障继续经同一队列，不占业务序号。

当前正式入口不提供 `AdvanceTime`，因此分片逻辑时间在该入口的整个生命周期内保持启动值；只有显式接入时间命令并完成到期处理后才能推进。审计时间和系统时间不推进该时钟。

开发环境的持久启动入口仅支持空状态和本地持久化，可选择逐条同步或 GroupCommit；去重命中不追加 WAL。批次内命令顺序应用于隔离候选，提交水位推进后才安装候选并回复。持久化错误停止分片，旧进程内启动入口不具备此语义。两目录要求及限制见 [WAL 说明](wal.md)。

## 原子性和事件顺序

市场路由与载荷范围检查在分配序号前执行。通过后根变更取得分片序号，在候选订单簿及登记表上构造批量撤单计划，按业务原序生成事件，并在安装候选状态之前封装完整事件。取消的活动预留迁入 `PendingR2`；金融状态仍为 Active，不伪造 `ReservationReleased`。命令响应返回已取消数量，不将汇总伪装成业务事件。零匹配是成功变更，消耗序号但不生成事件，汇总数量为零。订单及登记表的不变量损坏会停止分片，不作为普通业务拒绝继续运行。

根事件索引为 `0..=u32::MAX`。如果候选事件数超过可编码范围，候选簿及登记表均不提交，已分配序号保留，返回一条 `CommandRejected(ArithmeticOverflow)`，索引为零。不同于普通 Stop child 业务拒绝，事件容量不足是整条根命令规划失败。正式限价下单可产生真实 Trade；游标按实际成交推进，失败候选不安装。

事件身份 `(cluster_id, shard_id, shard_seq, event_index)` 随分片序号及事件索引确定。LocalDurable 恢复入口以已验证的快照和 WAL 前缀续接序号；调用方必须确保目录独占和可信身份，当前不提供跨进程租约或备节点晋升。空状态新建入口不应指向已有分片的数据目录。

## 分片内命令去重

`ShardHandle::submit_command` 的业务结果错误类型由 `RejectReason` 调整为 `FormalError`：原拒绝原因包含在 `FormalError::Rejected` 中，身份或意图冲突使用 `FormalError::ProtocolError`。显式标注旧错误类型或直接匹配 `RejectReason` 的调用方需要更新；外层的入队错误仍为 `ShardError`。

正式入口在路由检查后，以 `CommandId` 及市场、用户、业务载荷的结构相等性检查重复意图。相同意图命中时返回原序号、业务结果和事件范围，不重新执行、不分配新序号，也不重新发送事件批次。相同身份对应不同意图，或仍在窗口内的会话序号绑定另一命令时，返回 `FormalError::ProtocolError`；这不是新造的稳定业务原因码。路由版本、会话身份和审计时间不属于业务意图。

`IdempotencyConfig` 配置命令、会话和每会话别名容量；启动时预分配这些有限槽位。命令按首次执行顺序先进先出淘汰，命中不延长保留；淘汰时删除对应会话别名。旧序号若已无别名则回到 CommandId 检查，不凭最高序号单独拒绝。当前实现为线性查找，尚无性能承诺。

窗口只存在本分片进程内，不跨 shard、不跨重启，也不保证淘汰后的重试幂等。当前没有 EventJournal，因此重试无法取回遗失的首次事件批次。旧低层 Mutation 入口未接入去重。正式限价下单、市场批量撤单和分片 FenceOnly 共用该有限窗口。

## 限价下单、客户端身份与用户控制

正式下单先检查市场路由和载荷用户的控制 epoch，再检查命令与会话别名；因此旧路由或低于用户下限的重试也会先被拒绝。未命中时再检查 envelope 用户与载荷用户身份是否一致，且仍在分配序号前完成；已保留的 CommandId 改变 envelope 用户会触发协议冲突。首次执行在分配序号前检查实际活动订单总容量；容量已满返回 `EngineBusy`，即使新单可能立即成交也不会进入撮合。客户端身份可选；非空身份按用户隔离，在活动期和有限终结历史中禁止复用。活动项不因历史淘汰而消失；终结项按真实终结事件顺序进入先进先出历史，正式下单配置要求终结历史容量大于零。正式市场批量撤单同步终结相关客户端身份。

使用签名令牌绑定根命令、用户、订单、市场及可信费率版本和层级；按真实价格与数量计算资产需求并验证资产集合、覆盖和签名。订单、预留归属、客户端身份和成交游标先在候选状态执行，事件索引检查成功后一起安装。接受的预留保存首次执行的来源会话；成功重试复用原摘要，不再次接管预留。真实订单终结只把金融仍为 Active 的预留归属迁入 `PendingR2`，不生成虚构的资金释放事件。

FenceOnly 在去重前检查期望主节点 epoch，在候选状态将用户下限推进到旧值与新值的较大者并发出 `UserControlEpochAdvanced`；未知用户下限为零，有限容量满时新用户非零下限不能登记。该检查仅使用启动配置的进程内 epoch，不构成租约或跨分片 fencing。没有跨 shard 协调、生产恢复、HA、持久 FeeScheduleBook 或真实 R2；可信调用方配置不是持久费率簿。报价资产手续费的预留上界见[数值计算公式](numerical_formulas.md)，非报价资产手续费尚不支持。
