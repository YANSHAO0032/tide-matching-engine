# 命令与事件身份

当前正式命令入口使用 `CommandEnvelope` 携带命令身份、会话、客户端序号、可选市场／用户、路由版本及审计时间。审计时间仅保存为输入信息，不参与撮合或逻辑时间。`EventEnvelope` 按原序携带集群、分片、根命令序号、从零开始的事件索引、命令身份、逻辑时间、事件所属市场及业务载荷。当前并无持久化、二进制编码或命令去重。

## 正式入口支持范围

| 命令或范围 | 当前支持 |
|---|---|
| 市场范围 `MassCancelShard` | 在持有真实 `ReservationRegistry` 的分片中执行；`market_id`、scope 市场和路由版本须一致，当前仅支持无 envelope 用户身份的市场范围。 |
| 其他 MassCancel 范围 | 未通过正式入口开放；跨市场和用户控制须等待相应路由及控制契约。 |
| Place、Cancel、Amend、CancelReplace、Stop、市场控制 | 尚未通过正式入口开放。旧 runtime 低层入口只在无登记表模式使用，不代表完整正式生命周期。 |

正式模式启动须提供显式绑定市场的订单簿、完整登记表及初始逻辑时间；启动核验所有活动订单与预留归属，并拒绝初始时间已到期的普通及 Stop GTD 订单。当前尚无完整市场会话状态，调用方必须保证初始订单状态与逻辑时间来自同一可信执行点、DAY 订单所属交易时段仍有效；启动检查不证明会话一致性。调用方须保证输入来自可信执行上下文，当前不提供管理权限认证。正式模式拒绝旧低层 Mutation，避免绕过预留归属。查询和屏障继续经同一队列，不占业务序号。

当前正式入口不提供 `AdvanceTime`，因此分片逻辑时间在该入口的整个生命周期内保持启动值；只有显式接入时间命令并完成到期处理后才能推进。审计时间和系统时间不推进该时钟。

## 原子性和事件顺序

市场路由与载荷范围检查在分配序号前执行。通过后根变更取得分片序号，在候选订单簿及登记表上构造批量撤单计划，按业务原序生成事件，并在安装候选状态之前封装完整事件。取消的活动预留迁入 `PendingR2`；金融状态仍为 Active，不伪造 `ReservationReleased`。命令响应返回已取消数量，不将汇总伪装成业务事件。零匹配是成功变更，消耗序号但不生成事件，汇总数量为零。订单及登记表的不变量损坏会停止分片，不作为普通业务拒绝继续运行。

根事件索引为 `0..=u32::MAX`。如果候选事件数超过可编码范围，候选簿及登记表均不提交，已分配序号保留，返回一条 `CommandRejected(ArithmeticOverflow)`，索引为零。不同于普通 Stop child 业务拒绝，事件容量不足是整条根命令规划失败。当前开放的批量撤单不会产生真实 Trade，故不消耗 `TradeId`。

事件身份 `(cluster_id, shard_id, shard_seq, event_index)` 仅在同一运行中的分片生命周期且序号不复用时唯一；重启后序号从头分配。恢复和跨重启唯一性必须等待 WAL／快照。`CommandId` 仅关联根命令，不提供重复执行保护。
